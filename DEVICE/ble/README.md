# DEVICE/ble — BLE 통신 레이어

담당: 한지원. **`device.cpp`는 건드리지 않았습니다** — 정윤서 파트(센서 읽기,
자이로+IR 기반 위험도 판정 알고리즘)가 들어갈 자리라서 그대로 뒀습니다.

이 폴더는 "통신"만 다룹니다: GATT 서비스·특성 등록, 20바이트 프레임
인코딩, 경보 제한 재전송. 두 파트가 만나는 지점은 `comm_reference.ino`의
`fillSyntheticFrame()` 함수 하나입니다 — 지금은 가짜 사인파를 채우고
있고, 실제 알고리즘이 계산한 PERCLOS·pitch·위험도를 여기 넣어주면 됩니다.

## 파일

- **`protocol.h`** — GATT UUID, 20바이트 Live Metrics 구조체, Alert/Ack/Command
  포맷. `APP/lib/src/protocol/`의 Dart 코드와 **바이트 단위로 일치**하도록
  맞췄습니다 (gcc로 컴파일해서 Dart 인코더 출력과 대조 완료). UUID나 구조체
  레이아웃을 바꾸면 앱 쪽도 같이 바꿔야 합니다.
- **`comm_reference.ino`** — W1 검증용 참고 스케치. 센서 없이 이것만 보드에
  올리면 nRF Connect로 링크 전체를 확인할 수 있습니다 (앱 쪽 README의
  "W1 벤치 검증" 참고). 센서 붙을 때 `fillSyntheticFrame()`만 실측값으로
  바꾸면 되고, `device.cpp`에 통합하거나 반대로 이 파일의 GATT 등록 부분을
  `device.cpp`로 옮겨 붙여도 됩니다 — 편한 쪽으로 하시면 됩니다.

## 9/10 팀 결정 반영

- 센서는 **자이로(IMU) + IR 두 개만**. 심박·HRV는 제외 — 프레임의 해당
  자리를 `eye_closure`(0-255, 캘리브레이션된 눈 감김 정도) + `proximity_raw`
  (IR 원시값)로 바꿨습니다.
- `proximity_raw`를 그대로 보내는 이유: 하드웨어팀 캡처 8개를 분석해보니
  눈 뜬 상태 IR 기준값이 세션마다 60~92로 흔들려서, 앱에서 캘리브레이션
  화면을 만들려면 원시값이 필요합니다. 극성(감으면 오르는지 내리는지)도
  아직 미확인이라 벤치에서 눈 뜨고/감고 이 값이 어느 쪽으로 가는지 보고
  확정해야 합니다.
- 위험도 연산은 전부 보드에서, 앱은 표시만 — 이 프로토콜이 원래 그 전제로
  설계돼 있어서 이번 결정으로 바뀐 건 없습니다.

## 신뢰성 정책 (정윤서 파트 관련)

- 실시간 지표(Live Metrics)는 **Notify, 무확인**. 4~10 Hz라 한 샘플
  놓쳐도 다음 게 곧 옵니다.
- 위험 경보(Alert)는 **Indicate + 앱 레벨 ACK, 최대 3회 재전송**.
  `comm_reference.ino`의 `raiseAlert()` / `serviceAlertRetries()`가
  그 로직입니다. 3회 실패하면 폰 없이도 보안경 단독으로 진동·음성을
  계속 냅니다 — 안전 장비라 무한 재시도 대신 이렇게 했습니다.
- 자세한 근거는 앱 쪽 `README.md`의 "4. 신뢰성 기법" 참고.
